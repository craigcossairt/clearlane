## SUMMARY
Recommendation: use a stripped subset of Trellis. Take its guardrail hooks and harness adapters and write a new ~50-line AGENTS.md of your own. Do not use the full template. The model for that AGENTS.md is the one Craig wrote for his last hackathon, 3 days ago. That repo (~/Code/ai-visibility-check, Codex DevDay, code freeze Oct 24) had a 31-line AGENTS.md with a lanes table that gave each of Codex, Cursor, Grok Build and Claude Code a branch, the files it owns and a done-when line, and one command to run before pushing.

What Trellis is good for: one set of canonical hook scripts covers Claude, Cursor, Grok and Codex. They block edits to .env, secrets and lock files, format edited files, and inject git context at session start. That matters here because the data lane will hold API keys in .env. The rest is a poor fit for 44 hours:
- The 468-line AGENTS.md tells every agent to stop and confirm test seams before writing any test, to open draft PRs reviewed in a fresh context and by a second model, to attach before/after media to every PR, and to run the claim/lease protocol.
- The branch-claim check in the pre-push hook is on by default. It goes to the network on every push and blocks when it cannot tell.
- The 1,244-line hooks-ci.yml runs Linux and Windows jobs. Its steps assume the full template, so removing files without editing the workflow turns it red.

Setup time (my estimate, not measured): full template with all four harnesses wired and checked on Windows, 45-75 minutes. Stripped subset, 20-30 minutes. Plain repo, 10-15 minutes, but then nothing enforces the rules.

Trellis does not assume a stack, so Python plus TypeScript works. On this PC, though, ruff and black are not installed, so Python formatting quietly does nothing until ruff is. Prettier runs only if it is a project devDependency. A WSL bash.exe exists, so the Cursor and Grok hook files need Git Bash's full path.

Craig's own history cuts both ways. start-school ran full Trellis v1.3.1 with the push gate on and recorded 173 commits and 55 merges in about 23 hours. So the full template does not block speed, but the recent multi-harness hackathon used the lighter lanes pattern.

## RISKS
- Committing the Windows Git Bash path into .cursor/hooks.json and .grok/hooks/hooks.json breaks those hooks for any teammate on a Mac. Committing bare `bash` risks WSL on this PC.
- Cursor and Grok fail open if block-sensitive-files.sh is missing or misnamed (run-claude-hook.sh returns allow). A copy mistake would silently disable the .env guard there, so the deliberate-violation check in each harness is required.
- Codex edit hooks cover only apply_patch. Shell writes get past the sensitive-file check, and any edit to .codex/hooks.json needs re-trust in /hooks.
- Full-template risk: the claim layer is on by default and blocks pushes when offline, when user.email is unset, or when a human teammate's commits are on the same feature branch. Agents may lose time on bypass variables.
- Full-template risk: if Trellis is pruned without editing hooks-ci.yml, a public repo shows red CI to judges (the missing CREDITS.md or recommended-tooling.md step exits 1; the claim-branch suite steps are unconditional).
- Full-template risk: the 468-line AGENTS.md tells every agent to stop and confirm test seams, open draft PRs with second-model review, and attach before/after media. Across 4 agents this could cost hours.
- Two TDD/learn workflows are installed at user level (mattpocock-skills and gstack in Craig's plugin set), and Trellis's own docs flag them as colliding with its /tdd and /learn. Dropping .claude/commands/tdd.md in the subset removes that collision inside the repo.
- Setup-time numbers are estimates, not measurements.
